# MVP Requirements — Self-Programming App

## Концепция

Приложение помогает людям менять себя через действие. Пользователь выбирает навык, получает задания с нарастающей сложностью и рефлексирует после каждого. Аватар — визуальная метафора роста, а не цель сама по себе.

**Платформа:** Нативное мобильное приложение для Android. Релиз — RuStore (приоритет) и Google Play. iOS — после первой валидации продукта.

---

## Стек

- **Frontend**: React Native + Expo (TypeScript, NativeWind для стилей, Lucide React Native для иконок, Reanimated 3 для анимаций)
- **Backend/БД**: Supabase (auth + Postgres)
- **Сборка/деплой**: EAS Build → AAB для RuStore и Play Market
- **Push**: FCM (для устройств с Google Services) + RuStore Push SDK как fallback для устройств без GMS
- **Дев-окружение**: Expo Dev Client + Android Emulator (Android Studio AVD) — основной способ смотреть приложение с компьютера. Expo Web — для быстрых проверок вёрстки

---

## Дизайн-направление

**Aesthetic**: Тёмная тема. Органично-футуристический стиль — как будто живая система, которая дышит. Не геймификация в духе Duolingo, а что-то серьёзное и медитативное. Вдохновение: Notion meets Dark Souls meets психологический дневник.

**Типографика**: Display-шрифт с характером (например, Fraunces или Playfair Display) для заголовков + моноширинный (JetBrains Mono) для деталей и статистики. Контраст между органикой и точностью.

**Цвета**: Почти-чёрный фон (#0A0A0F), тёплый кремовый текст (#F0EAD6), единственный акцент — приглушённый янтарь (#C8923A). Никаких градиентов из фиолетового.

**Анимации**: Минималистичные, но весомые. Появление элементов — как будто они проявляются из темноты. Прогресс-бар дышит. Переходы — плавные, без суеты.

## Экраны MVP (5 экранов)

### 1. Онбординг / Создание аватара
- Поле: имя аватара (не настоящее имя пользователя)
- Выбор одного навыка из 3 доступных на MVP:
  - 🗣 Общительность
  - 🧠 Фокус
  - 💪 Дисциплина
- Короткое описание что изменится через 21 день (1-2 предложения под каждым навыком)
- Кнопка "Начать путь"
- **Нет регистрации на этом шаге** — сначала вовлечение, потом аккаунт

### 2. Главный экран (Dashboard)
- Имя аватара + текущий уровень навыка (1 из 5)
- Визуальный индикатор прогресса по текущему уровню (выполнено N из M заданий уровня)
- Текущее задание дня — карточка с:
  - Названием задания
  - Описанием (2-4 предложения)
  - Уровнем сложности (метка)
- Кнопка "Выполнено" + кнопка "Перенести на завтра" (см. правила в разделе "Логика прогрессии")
- Стрик — сколько дней подряд выполняются задания

### 3. Экран задания (детальный)
- Полное описание задания
- Блок "Как это сделать" — 3-4 конкретных совета под задание
- Примеры из жизни (1 короткий пример)
- Таймер (опционально — для заданий где нужно время)
- Кнопка "Я сделал это"

### 4. Рефлексия (после выполнения)
- 3 вопроса, не больше:
  1. "Что было самым сложным?" (свободный текст, до 500 символов)
  2. "Что удивило?" (свободный текст, до 500 символов)
  3. Слайдер: "Насколько некомфортно было?" (1-10)
- После сохранения — короткое сообщение от аватара (на MVP — из пресетов, подобранных по дискомфорт-скору)
- Переход на дашборд с обновлённым прогрессом

### 5. Профиль / История
- Список выполненных заданий с датами
- Ответы рефлексии (личный журнал)
- Текущий уровень навыка и что откроется на следующем
- Кнопка смены навыка (с предупреждением что прогресс сбросится)

## Логика прогрессии

### Подача задания на день
1. На дашборде показывается одно задание из пула текущего уровня — рандом из ещё не выполненных вариантов
2. Если все варианты текущего уровня выполнены, но условие повышения не достигнуто — берётся повторно из выполненных (с приоритетом разнообразия)
3. После выполнения и рефлексии — обновляется прогресс

### Структура контента
Для каждого навыка: **5 уровней × 4-5 заданий-вариантов** ≈ 22 задания. Это покрывает обещание "21 день".

Внутри одного уровня варианты — это одна и та же идея в разных формулировках/контекстах (см. примеры для "Общительность" уровня 1 ниже).

### Правила перехода уровня

Уровень растёт, когда выполнено N заданий уровня **И** средний дискомфорт на них ≥ D:

| Переход | N выполнений | Средний дискомфорт |
|---------|--------------|---------------------|
| 1 → 2   | 3            | ≥ 3                 |
| 2 → 3   | 4            | ≥ 4                 |
| 3 → 4   | 4            | ≥ 5                 |
| 4 → 5   | 4            | ≥ 5                 |
| 5 → финиш | 4          | ≥ 5                 |

**Зачем порог дискомфорта:** защита от "проставил галочку не выходя из дома". Если средний дискомфорт ниже порога — уровень не растёт, даются те же варианты, пока человек реально не выйдет из зоны комфорта.

### Стрик и пропуски
- Календарный день с выполненным заданием = `streak + 1`
- "Перенести на завтра" — **2 раза за весь 21-дневный путь**, стрик не сбрасывается
- Пропуск без переноса — `streak = 0`, но **уровень и выполненные задания сохраняются**. Мы не наказываем людей за реальную жизнь

## Контент: Навык "Общительность"

Для MVP первый вариант каждого уровня прописан, остальные 3-4 варианта на уровень нужно дописать перед разработкой.

### Уровень 1 — Инициация контакта
**Задание (вариант 1)**: Поздоровайся с 3 незнакомыми людьми сегодня. Просто "привет" или кивок — этого достаточно.

**Советы**:
- Начни с людей в лифте или на кассе — там это нормально
- Не жди подходящего момента, просто сделай
- Если страшно — скажи себе: "Мой аватар сделал бы это не задумываясь"

**Уровень дискомфорта**: низкий

---

### Уровень 2 — Короткий разговор
**Задание (вариант 1)**: Начни и удержи разговор с незнакомым человеком минимум 2 минуты.

**Советы**:
- Используй контекст ситуации — очередь, кофейня, лифт
- Открытый вопрос лучше закрытого: "Как вам это место?" вместо "Вам нравится?"
- Твоя цель — не понравиться, а просто поговорить

**Уровень дискомфорта**: средний

---

### Уровень 3 — Личный вопрос
**Задание (вариант 1)**: Узнай что-то личное о незнакомом человеке — чем занимается, что любит.

**Советы**:
- Люди любят говорить о себе — тебе не надо быть интересным, надо быть любопытным
- Слушай активно: кивай, переспрашивай
- Не торопись заполнять паузы

**Уровень дискомфорта**: средний-высокий

---

### Уровень 4 — Инициатива
**Задание (вариант 1)**: Предложи продолжить общение — обменяйся контактами или предложи встретиться снова.

**Советы**:
- Худшее что может случиться — человек скажет нет. Это не катастрофа
- Конкретное предложение лучше размытого: "Давай как-нибудь" хуже чем "Ты был бы не против встретиться на кофе на этой неделе?"

**Уровень дискомфорта**: высокий

---

### Уровень 5 — Глубина
**Задание (вариант 1)**: Проведи разговор где ты откроешься сам — расскажи что-то личное незнакомому человеку.

**Советы**:
- Уязвимость создаёт доверие быстрее чем что-либо другое
- Не надо рассказывать секреты — достаточно сказать что ты думаешь на самом деле

**Уровень дискомфорта**: очень высокий

---

*(Контент для "Фокус" и "Дисциплина" — по той же структуре: 5 уровней × 4-5 вариантов, добавить перед разработкой.)*

## Технические требования

### Auth
- Регистрация через email (Supabase Auth)
- Появляется только когда пользователь нажимает "Выполнено" в первый раз — не раньше
- Данные до регистрации сохраняются в AsyncStorage и мёржатся после
- AsyncStorage изолирован по устройству: переустановка приложения до регистрации = потеря данных. На MVP приемлемо

### База данных (Supabase)

```
users
  id, email, created_at

avatars
  id, user_id, name, skill_id,
  current_level (1-5),
  level_progress (int — сколько заданий выполнено на текущем уровне),
  streak (int),
  deferrals_used (int, лимит 2),
  last_completed_at,
  notification_time (time)

skills
  id, name, description

tasks
  id, skill_id, level (1-5), variant_order (1-N),
  title, description, tips, difficulty (1-5)

completions
  id, avatar_id, task_id, completed_at,
  discomfort_score (1-10),
  reflection_hard (text, до 500),
  reflection_surprise (text, до 500),
  was_deferred (bool)
```

### Уведомления
- **Основной канал**: FCM, инициируется Supabase Edge Function по расписанию
- **Fallback** для устройств без Google Services: RuStore Push SDK
- Одно напоминание в день в выбранное пользователем время
- Простое сообщение от имени аватара

### Контент-модерация
Базовый фильтр свободного текста рефлексии (анти-мат / анти-спам) перед сохранением. Требование для прохождения ревью RuStore.

### Просмотр с компьютера во время разработки
- **Android Emulator** (Android Studio AVD) — основной способ. Полная нативная среда, push можно эмулировать
- **Expo Web** (`expo start --web`) — для быстрых правок вёрстки. Не все нативные модули и анимации Reanimated 3 идентичны
- **Expo Dev Client** на эмуляторе с hot reload — рабочий цикл

---

## Что НЕ входит в MVP

- Социальные функции (сравнение с другими, друзья)
- Кастомизация внешности аватара
- Более 3 навыков
- Платёжная система
- iOS-версия (после валидации)
- AI-генерация заданий
- Геймификация (бейджи, лидербоарды)
- Несколько активных навыков на одном аватаре (заложено как направление развития, см. ниже)

---

## Направление развития (после MVP)

**Аватар как RPG-персонаж.** Пользователь создаёт "себя", аватар содержит несколько навыков одновременно, каждый качается параллельно через ежедневные задания. На экране аватара — статистика по всем навыкам, как профиль персонажа.

В MVP — один активный навык, но на экране аватара отображаются все 3 ветки (две заблокированы со статусом "откроются позже"). Это закладывает метафору, не раздувая объём.

---

## Метрики успеха MVP

1. **Day 7 retention** ≥ 30% — возвращаются ли люди через неделю
2. **Task completion rate** ≥ 50% — выполняют ли задания или только смотрят
3. **Reflection fill rate** — заполняют ли рефлексию (сигнал вовлечённости)
4. **Streak length** — средняя длина стрика до отвала
5. **Level-up rate** — какой % пользователей доходит до уровня 2, 3, 4, 5

---

## Порядок разработки

1. Инициализация Expo-проекта + базовая навигация + Android Emulator настроен
2. Supabase — схема БД + auth
3. Онбординг (без регистрации, локально через AsyncStorage)
4. Dashboard + карточка задания
5. Экран детального задания
6. Рефлексия + логика прогрессии (правила уровня + стрик + перенос)
7. Lazy registration (при первом "Выполнено") + мёрдж локальных данных
8. История / Профиль
9. Push-уведомления (FCM + RuStore Push fallback)
10. Базовая модерация текста рефлексии
11. Финальная полировка дизайна (анимации, типографика)
12. Сборка AAB → подача в RuStore и Google Play
